# bnn — биологически правдоподобное локальное обучение

Хобби-исследовательский проект: локальные three-factor правила обучения с сегрегированным апикальным каналом, как альтернатива backprop. Проверка на XOR, MNIST, возможно CIFAR-10.

## Документы

- `docs/roadmap.md` — план работ по сессиям, оценки, требования к железу, гигиена процесса

Перед содержательной работой сверяйся с `research-plan.md`: терминология и формулы там.

## Ключевые термины

- **forward-канал (базаль)** — обычное вычисление `post = activation(W_ff · pre)`
- **апикальный канал (learning)** — отдельный вход `a`, влияет **только** на пластичность, на forward-выход не влияет никогда
- **`e = a · psi(z)`** — локальная ошибка нейрона; `psi` — псевдопроизводная (`1[z>0]` для ReLU), заменяет `f'`
- **`W_fb`** — матрица доставки learning-сигнала, случайная фиксированная с нулевым средним. **Не** транспонированная `W_ff` (кроме режима верификации)
- **trace** — eligibility trace, затухающая память о ко-активации
- **`K`** — размерность learning-сигнала: 1 (скалярный дофамин) … dim(выход) (полная DFA)

## Конвенции реализации — не нарушать

Это сознательные отклонения от обычного PyTorch, не недосмотр.

- **Не использовать AMP / fp16 для локальных правил.** `lr · outer(e, pre)` — крошечное слагаемое к весу порядка единицы, в fp16 округляется до нуля молча. Loss scaling отсутствует, поскольку нет оптимизатора. Веса и обновления только fp32. TF32 включать можно и нужно.
- **Не заменять ручное обновление весов на `torch.optim`.** Обновления локальные и ручные по определению; autograd используется исключительно как калькулятор эталонного градиента для диагностики alignment.
- **Апикальный сигнал не добавляется к forward-выходу.** Сегрегация каналов — проверяемая гипотеза проекта, а не деталь реализации.
- **Learning-сигнал всегда используется как отклонение от baseline** (`a − baseline`). Без вычитания — runaway.
- **`softmax` в WTA-слоях — по каналам (`dim=1`), не по пространству.** Ошибка тихая: сеть просто учится плохо.
- **Датасет целиком в VRAM, `DataLoader` не использовать.** MNIST 188 МБ, CIFAR-10 614 МБ. На Windows `num_workers>0` особенно медленный из-за `spawn`.
- **`pathlib.Path` везде**, никакой конкатенации путей строками.
- **Очередь прогонов — на Python** (`ProcessPoolExecutor`), не shell-скрипт: должно работать одинаково на Windows, в WSL и в облаке.
- **Раннер печатает `torch.cuda.is_available()` и имя устройства** в лог каждого прогона. На Windows легко случайно поставить CPU-сборку torch.
- **Каждый прогон пишет в свою папку** `runs/<id>/`. Windows блокирует открытые файлы, параллельная запись в общий лог упадёт.

## Структура

```
src/bioplast/
  layers/       ThreeFactorLayer, HebbLayer, ConvHebbLayer, LocallyConnected
  signals/      источники апикального сигнала (supervised / predictive / reward)
  delivery/     W_fb: random, topographic, learnable, transposed
  diagnostics/  alignment, runaway, win-histogram, sparsity
  runner/       config → run → metrics.json
  viz/          plot.py, report.py
experiments/    скрипты конкретных экспериментов
runs/           результаты прогонов (в .gitignore)
docs/
```

**Источник апикального сигнала — подключаемый объект, а не `if` внутри слоя.** Вся гипотеза 1 держится на переключаемости режимов UL/SSL/supervised/RL сменой источника.

**Правило трёх:** код выносится в `src/` только когда одно и то же написано трижды. В блоках 0–2 дублирование в `experiments/` допустимо.

## Тесты

Центральный тест корректности: при `W_fb = W_ffᵀ` величина `e` должна совпадать с `δ` из autograd. Это отделяет баги реализации от вопросов «работает ли идея».

## Стиль

- Ноутбуки — только для разведки. Библиотечный код в ноутбуках не живёт никогда.
- Правки в документах — по разделам, отдельными дифами, не пачкой.
- Отрицательные результаты фиксируются наравне с положительными: «где именно ломается alignment» ценнее очередного процента точности.
