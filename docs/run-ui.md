# Веб-интерфейс прогонов

Локальный UI блока V предназначен для просмотра и сравнения результатов из
`runs/<id>/`. Он также умеет создать повторный запуск: исходные конфиги и
артефакты остаются только для чтения, а изменённая копия получает собственный
каталог и выполняется через очередь раннера.

## Запуск и остановка

Из корня проекта:

```powershell
uv run uvicorn bioplast.viz.api:app --reload
```

Открыть `http://127.0.0.1:8000/runs`. Остановка — `Ctrl+C` в терминале, где
работает Uvicorn. Другой каталог результатов задаётся перед запуском:

```powershell
$env:BIOPLAST_RUNS_DIR = "D:\experiments\runs"
uv run uvicorn bioplast.viz.api:app --reload
```

Интерфейс локальный и не содержит авторизации. Не публикуйте порт наружу и не
меняйте `--host` на `0.0.0.0`, пока для этого не появится отдельная задача.

## Каталог запусков

Страница `/runs` показывает сводку и таблицу прогонов, новые первыми.

- Карточки сверху считают показанные завершённые, активные и упавшие прогоны.
- Фильтры ограничивают список по статусу, точному имени эксперимента, seed и
  интервалу времени. Кнопка «Сбросить» возвращает полный каталог.
- Автообновление перечитывает список раз в пять секунд; его можно отключить.
- Статус `failed` выделяется красным. Метка `dirty` означает, что прогон сделан
  на незакоммиченном рабочем дереве и точно не воспроизводим одним git-хешем.
- В колонке «Итог» показываются первые скалярные значения из `metrics.final`.
- Повреждённый каталог не скрывается и не роняет весь экран: причина появляется
  в отдельном блоке «Нечитаемые каталоги».

Поддерживаются как новые прогоны с `run.json`, так и прежние каталоги блока 0.
У legacy-прогонов манифест синтезируется в памяти; файлы на диске не меняются.

## Карточка прогона

Клик по идентификатору открывает `/runs/<id>`. Заголовок показывает эксперимент,
статус, датасет, модель, seed, время и длительность.

### Диагностические предупреждения

- Для `failed` сверху показывается сохранённый traceback из `metrics.error`.
- Для `git.dirty: true` показывается предупреждение `DIRTY RUN` и список
  изменённых файлов, если он был сохранён раннером.
- Метка `legacy contract` означает адаптированный старый прогон, а не ошибку.

### Параметры, окружение и код

Три таблицы выводят данные без переименования полей:

- `config.json` — фактические параметры эксперимента;
- `metrics.env` — Python, PyTorch, CUDA, выбранное устройство и пиковая VRAM;
- `metrics.git` — коммит, ветка, dirty-флаг и изменённые файлы.

Итоговые значения `metrics.final` вынесены в отдельные карточки над таблицами.

### Интерактивные графики

Числовые ряды из `metrics.epochs` автоматически группируются по префиксу ключа:
`loss/*`, `acc/*`, `w_norm/*`, `act_rms/*` и так далее. Новый ключ метрики
появляется без изменения UI.

На графике можно:

- после активации навести курсор и увидеть точное значение на шаге/эпохе;
- кликнуть по графику и только после этого панорамировать его перетаскиванием
  левой кнопкой мыши или масштабировать колёсиком;
- кнопкой «Сбросить масштаб» вернуть исходные оси; клик вне графика или Escape
  снова освобождает колёсико для прокрутки страницы;
- скрыть и вернуть кривую кликом по легенде;
- двойным кликом по графику вернуть исходный масштаб.

Для положительных норм `w_norm`, `grad_norm`, `act_rms`, `act_max` автоматически
используется логарифмическая ось. Plotly.js отдаётся локально сервером; интернет
для графиков не нужен.

### Модель и веса

Секция «Модель» читает канонический `model.json`, если эксперимент вернул
`ModelArtifacts`, а раннер сохранил инспекционный снимок. Для backprop-XOR и
backprop-MNIST она показывает граф `hidden → output`.
На каждом узле показана форма единственной матрицы `weight`, например `8 × 2`,
а не ведущая batch-размерность входов и выходов. Клик по узлу выбирает слой и
открывает его тип, активацию, формы `weight` и `bias`, число параметров и список
доступных тензоров.

Размер батча вынесен в сводку над графом. `Батч снимка` берётся из
`capture_batch_size` — фактического observation-forward, которым инспектор снял
формы и значения. Если конфиг содержит `batch_size` или `batch`, рядом отдельно
показывается `Батч обучения`; он может отличаться от диагностического снимка и
не меняет размер матрицы весов.

Внутри слоя можно переключаться между `weight`, `bias` и другими сохранёнными
тензорами. Для каждого выводятся dtype, форма, режим значений и summary:
количество элементов, число конечных и неконечных значений, min/max/mean/std,
L1/L2-нормы и sparsity. Если инспектор включил полные малые значения, ниже
появляются прокручиваемая числовая таблица и heatmap: отрицательные значения
красные, положительные бирюзовые, насыщенность показывает абсолютную величину,
а точное число доступно во всплывающей подсказке ячейки.

Большой, пустой или содержащий NaN/Infinity тензор остаётся доступен через
summary, а UI явно показывает причину отсутствия полной матрицы. Отсутствующий
`model.json` — нормальное состояние для старого прогона; у активного запуска UI
ждёт появления снимка после безопасной точки экспорта. Повреждение или
неподдерживаемая версия файла показываются внутри секции модели и не ломают
остальную карточку.

У MNIST матрица первого слоя `256 × 784` превышает лимит raw values, поэтому
показываются её форма и summary без передачи сотен тысяч чисел в JSON. Малые
тензоры того же запуска остаются доступны полностью. Повторный запуск старого
MNIST-конфига использует текущий общий интерфейс и создаёт новые модельные
артефакты, не изменяя каталог родителя.

`checkpoint.pt` остаётся отдельным бинарным артефактом для worker-процесса. Его
можно скачать из списка артефактов, но браузер и backend UI не загружают из него
PyTorch-модель.

В следующих сессиях секция модели станет контейнером нескольких вкладок:

- «Нейроны» — схема «кружки и стрелки» для малых сетей; в V.9 она получит
  подсветку активаций и связей выбранного forward;
- «Вычисления» — операции вроде `Linear → ReLU → Linear`, формы тензоров и
  параметры;
- «Тензоры» — существующие summary, числа и heatmap; в V.10 добавятся
  `W_before`, `ΔW`, `W_after`, loss и граница решений;
- для больших моделей — обзор подсистем, раскрываемая иерархия, поток тензоров,
  агрегированная диагностика и профиль ресурсов вместо полного графа связей.

Представления Bayesian-весов (`μ`, `σ`, posterior/prior), embeddings, attention
и attribution подключаются позднее через типизированные артефакты соответствующих
моделей. UI не выводит их из имени эксперимента и не десериализует checkpoint.

### Live-tail лога

Лог дочитывается порциями по байтовому offset и не передаётся целиком при каждом
обновлении.

- «следить» — опрашивать `run.log` раз в 1.5 секунды;
- «вниз» — автоматически прокручивать к новым строкам;
- «С начала» — очистить окно и перечитать лог с нулевого offset;
- «Скачать» — открыть исходный файл лога как артефакт.

Сервер дочитывает границу UTF-8, поэтому кириллический символ не разрезается
между двумя ответами. Если `run.log` ещё не создан, экран сообщает об этом и
продолжает опрос.

### Артефакты

Нижний блок перечисляет все файлы внутри каталога прогона, включая вложенные
`plots/`, будущие `snapshots/` и бинарный `checkpoint.pt`: относительный путь,
размер и время изменения. Клик открывает или скачивает исходный файл. UI читает
граф и статистики из `model.json`, но не десериализует checkpoint. Пути с `..`,
абсолютные пути и симлинки наружу `runs/<id>/` сервер отклоняет.

### Повторный запуск

Блок «Повторный запуск» появляется в карточке завершённого, упавшего или
отменённого прогона. Пока исходный прогон находится в `queued`, `running` или
`paused`, форма объясняет, что нужно дождаться терминального состояния.

- Форма показывает только разрешённые гиперпараметры; тип числа, boolean или
  JSON-массива сохраняется при редактировании.
- Diff обновляется до отправки и показывает исходное и новое значение. Пустой
  diff допустим: так можно повторить тот же конфиг с тем же seed.
- Кнопка «Вернуть исходные» сбрасывает все поля без обращения к серверу.
- `experiment`, модель, датасет, исследовательская сессия, метка, пути и сложные
  вложенные структуры зафиксированы. Добавлять и удалять ключи через UI нельзя.
- После «Поставить в очередь» браузер открывает карточку нового запуска. Сначала
  она имеет статус `queued`, а лог и метрики появляются после старта процесса.

Новый `config.json` содержит `parent_run_id` исходного запуска; тот же идентификатор
записан в `run.json`, а карточка ребёнка содержит ссылку назад. Исходный каталог
не изменяется. Число параллельных процессов задаётся переменной
`BIOPLAST_RUN_WORKERS` перед запуском Uvicorn, по умолчанию используется один.

## Сравнение запусков

Страница `/compare` доступна из верхнего меню и каталога. В карточке повторного
запуска ссылка «Сравнить с родителем» сразу выбирает родителя как baseline, а
текущий запуск — как кандидата.

- Baseline служит точкой отсчёта; одновременно можно выбрать до четырёх
  кандидатов. Выбор сохраняется в URL, поэтому сравнение можно открыть повторно.
- Таблица параметров показывает только различающиеся поля `config.json`;
  служебный `parent_run_id` в сравнение не входит.
- Таблица итогов показывает числовые значения, абсолютную дельту
  `кандидат − baseline` и процент только при ненулевом baseline.
- На общих графиках цвет всегда обозначает запуск, а стиль линии — метрику.
  Используются только сохранённые координаты `step`/`epoch`; пропуски не
  соединяются выдуманными точками. Baseline рисуется широкой линией с открытыми
  маркерами, поэтому остаётся виден даже под совпадающей кривой кандидата.
- Другой эксперимент, датасет, модель или ось шага показываются в блоке
  ограничений. Если конкретного ряда у запуска нет, это подписано под графиком.

Экран ничего не пересчитывает и не изменяет в каталогах запусков: он сравнивает
только сохранённые артефакты.

## Текущие ограничения

После V.7 браузер уже показывает граф backprop-XOR, слои, статистики, числа и
heatmap малых весов. Ещё нет:

- pause/resume/step и регулируемой задержки — V.8;
- ручного входа и пошагового XOR — V.9–V.10.

Полный автоматический smoke-тест в настоящем браузере запланирован на V.11.
Сейчас серверные страницы, локальные assets, API и данные покрыты pytest.

## Если экран пуст

1. Проверить `GET http://127.0.0.1:8000/api/health`: ответ содержит фактический
   абсолютный `runs_dir`.
2. Убедиться, что в нём есть подкаталоги с `config.json` или `run.json`.
3. Посмотреть блок «Нечитаемые каталоги» и терминал Uvicorn.
4. Если порт занят, выбрать другой: `--port 8001`, затем открыть
   `http://127.0.0.1:8001/runs`.
