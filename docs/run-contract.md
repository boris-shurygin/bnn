# Контракт артефактов прогона

Версия 1 вводится в сессии V.1. Каталог `runs/<id>/` остаётся источником истины;
контракт нужен браузерному приложению и другим читателям, но не требует базы
данных и не даёт им доступа к живым объектам PyTorch.

## Правила совместимости

- Каждый новый JSON-объект содержит `schema_version: 1` и `kind`.
- Читатель принимает только явно поддерживаемые версии и сообщает ошибку вместо
  догадок о неизвестной схеме.
- Старый прогон без `run.json` читается через адаптер из `config.json`,
  `metrics.json` и имени каталога. Адаптер ничего не записывает и помечает
  результат `adapted_from_legacy: true`.
- Старый `metrics.status: ok` нормализуется в `completed`; прежний
  `metrics.json` не меняется, чтобы не ломать раннер, графики и очередь.
- Пути артефактов всегда относительны каталогу прогона и не содержат `..`.

## `run.json`

Манифест жизненного цикла создаётся атомарно со статусом `running` до запуска
эксперимента и атомарно заменяется после него. Допустимые состояния:
`queued`, `running`, `paused`, `completed`, `failed`, `cancelled`.

Обязательные для UI поля: `run_id`, `status`, `experiment`, `started_at`,
`updated_at`, `finished_at`, `duration_sec`, `parent_run_id` и словарь
`artifacts`. Время новых прогонов — ISO 8601 с UTC offset.

## `model.json`

Описывает модель без сериализации самой модели: имя, упорядоченный список слоёв,
их типы, входные и выходные формы, активации, число параметров, доступные тензоры
и связи между слоями. `kind` связи отличает forward-канал от learning-канала.
Идентификаторы слоёв уникальны; каждая связь обязана ссылаться на существующие
слои.

## `events.jsonl`

Одна строка — одно событие с `run_id`, монотонным `seq`, временем `occurred_at`,
`type`, опциональными `step`, `phase`, `layer_id`, скалярами и сообщением.
Большие значения в JSON не встраиваются: поле `snapshot` содержит относительную
ссылку на `snapshots/<seq>.npz`. Запись завершается переводом строки и `flush`,
поэтому тот же файл можно читать после завершения и показывать через live-tail.
