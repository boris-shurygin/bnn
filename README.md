# bnn — биологически правдоподобное локальное обучение

Хобби-исследование локальных three-factor правил обучения с сегрегированным
апикальным каналом как альтернативы backprop. Проверка на XOR и MNIST.

## Запуск

```bash
uv sync --group dev
uv run pytest

# один прогон
uv run python -m bioplast.runner configs/mnist_mlp_backprop.json

# свип: базовый конфиг × сетка значений → очередь → 3 процесса параллельно
uv run python -m bioplast.runner.sweep configs/xor_backprop.json --set seed=0,1,2 --out queue
uv run python -m bioplast.runner queue --workers 3

# графики из metrics.json
uv run python -m bioplast.viz runs --all

# локальный каталог прогонов и интерактивные графики
uv run python -m bioplast.viz serve
# открыть http://127.0.0.1:8000/runs

# сквозная проверка API, очереди, debug worker и динамического DOM браузера
uv run python -m bioplast.viz smoke
```

Каждый прогон пишет в свою папку `runs/<id>/`: `config.json`, `run.json`,
`metrics.json`, `run.log` и артефакты эксперимента. Эксперименты возвращают
раннеру единый `ExperimentResult`; если в нём есть PyTorch-модель, раннер всегда
создаёт `model.json` для визуализатора и бинарный `checkpoint.pt` с полными
весами и состоянием оптимизатора. Этой общей политикой пользуются backprop-XOR и
backprop-MNIST. Ручных шагов нет ни одного — прогон полностью описан конфигом.

## Команды рабочего ритуала

В Codex доступны два repo-scoped skill, которые вызываются явно:

```text
$finish-stage
/compact
$continue-work
```

`$finish-stage` проверяет готовый этап, коммитит рабочую ветку, перебазирует её
на `main`, выполняет fast-forward merge, обновляет `LOG.md` только на `main` и
пушит результат. `/compact` — встроенная команда интерфейса Codex, поэтому она
выполняется отдельно. `$continue-work` полностью перечитывает правила и
каноническую документацию, восстанавливает ближайшее действие и продолжает его;
команда полезна также после нового чата или долгого перерыва.

## Имена прогонов

```
runs/20260808-095245-ses0.4-mnist-mlp-784-256-10-s0-bp/
     └──────┬──────┘ └─┬──┘ └─┬─┘ └──────┬───────┘ │  └┬┘
       дата и время  сессия  данные   модель      сид  комментарий
```

Метка времени идёт первой, поэтому сортировка папок по имени совпадает с
хронологической. Читаемые компоненты берутся из полей конфига `session`,
`dataset`, `model`, `seed`, `tag`; отсутствующие пропускаются.

Файлы конфигов в `queue/` именуются **без** метки времени
(`ses0.4-mnist-mlp-784-256-10-s0-bp-4d0835.json`): перегенерация свипа должна
перезаписывать те же файлы, а не плодить дубли. Шесть шестнадцатеричных
знаков — хеш конфига, он разводит варианты, различающиеся полями, которых нет
в читаемой части имени.

## Текущее состояние

Блоки 0 и V закрыты: раннер с очередью, диагностика v0, графики,
backprop-эталоны, контракт артефактов, API, браузерный просмотр, повторный запуск,
сравнение baseline с кандидатами и независимый от UI экспорт графов backprop-XOR
и MNIST со статистиками и preview малых весов. Карточка запуска визуализирует граф,
слои, tensor summary, числовые таблицы и heatmap малых весов. Полное состояние
модели и Adam хранится отдельно в бинарном checkpoint. Кооперативное управление
уже работает: карточка отправляет `pause`, `resume`, `step`, `set_delay` и
`cancel`, а worker применяет их между атомарными шагами через `commands.jsonl`.
Для завершённого backprop-XOR можно открыть дочернюю интерактивную сессию,
выбрать одну из четырёх точек или подать два числа вручную и выполнить forward
по слоям. Активации и вклад связей показываются на схеме «кружки и стрелки» из
согласованных snapshots worker-процесса. Main/debug workers уже разделены;
activity lease освобождает забытые debug-сессии,
а recovery-поколения продолжают тот же `run_id` после гибернации или потери
процесса. Обычное обучение XOR и MNIST также возобновляется после потери
main worker: recovery сохраняет model/optimizer, точный progress cursor,
permutation MNIST и состояния Python/NumPy/torch CPU/CUDA RNG. Backprop-XOR
публикует согласованные снимки атомарных train-step: точные параметры до шага,
фактическую `ΔW` Adam, параметры после шага, loss и сетку границы решений.
Карточка воспроизводит их как heatmap-анимацию; ручной `step` использует тот же
control path и всегда создаёт кадр. V.13 добавила allowlist-реестр
debug-адаптеров: тот же протокол теперь открывает MNIST-сессию, принимает индекс
test-примера и выполняет MLP по одному слою. Для больших представлений UI
показывает 28×28 preview, top-k, иерархию модулей, поток форм/dtype и агрегаты
активаций без передачи полных весов или живых тензоров. V.14 добавила
принадлежащую приложению команду `serve`, настоящий restart-тест между слоями и
одно-командный smoke через реальный HTTP API, очередь, debug worker и headless
Chrome/Chromium/Edge. Следующий шаг — блок 1, сессия 1.0: зафиксировать формулы
локального правила и размерности перед реализацией `ThreeFactorLayer`.
